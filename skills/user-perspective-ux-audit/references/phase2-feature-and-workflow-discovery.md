# 阶段二审查细则：无提示全功能自主探索与工作流完通审计 (Stage 2 Discovery & Completion)

只有在**阶段一（第一印象、观感、易读性）门禁通过**后，才启用本文档。

传统 UI 测试的最大漏洞是“逛街式浅点”——盲测员点开几个显眼按钮、开关一两个弹窗就收工，导致**入口藏得太深的功能（幽灵功能）**和**做到一半卡死的业务断流**根本测不出来。阶段二通过**“主控暗建全量底账 + 盲测员两轮递进通关 + 双向差集对账”**，系统性测量新用户在**完全没有提示**下到底能发现多少功能、跑通多少工作流。

---

## 一、 主控暗建《全量功能与工作流底账》（绝密，严禁泄露给盲测员）

在派遣阶段二盲测子代理之前，**主控协调者（Coordinator）**必须先静默扫描代码仓库的路由表、页面组件、右键事件（`onContextMenu`）、文本划词浮层、拖拽区（Drag & Drop）、快捷键监听、设置子项与后端接口，整理出内部标准答案卷（**绝不能写进给盲测员的 Prompt**）：

### 1.1 全量功能清单 (`F-01 .. F-N`)
列出软件提供给终端用户的**每一项交互能力**，特别要显式清点“非显性入口”：
- 常规导航模块与主操作按钮（CRUD、搜索、筛选、排序、分页）；
- 次级与上下文功能（右键菜单、文字划选浮层、拖拽上传/排序、批量选择、导入/导出、快捷键）；
- 个人偏好、主题/语言、通知/定时、权限或协作功能。

### 1.2 端到端核心工作流 (`W-01 .. W-M`)
将孤立按钮串联成用户真正为了达成目的而做的完整闭环，并为每一条设定严格的 **完成验收标准（Definition of Done, DoD）**：
- 格式：`工作流编号 | 目标描述 | 完整步骤链 | 最终产物 DoD`
- 示例：`W-01 | 资料导入与知识问答闭环 | 创建工作区 → 上传本地文档 → 在对话中提问并引用 → 划选回答存为知识卡 → 审核确认生效 → 在图谱页查看关联节点`
- **铁律**：仅点开弹窗看一眼、或输入一半就取消，**计为 0% 完成度**；必须真实提交并看到下游消费生效，才算跑通 DoD。

## 二、 第 1 轮：100% 纯无提示自主深度通关 (Pass 1 — Zero-Hint Walkthrough)

派遣盲测子代理（可继续沿用刚刚在阶段一完成复检的纯净盲测子代理，或新拉起盲测子代理，**严禁透露底账里的任何功能名称或流程提示**）：

### 2.1 探索纪律
1. **自主立目标、做到底**：盲测员只能依靠阶段一所见及界面自身的引导，自己推断“普通用户拿这个软件最想干成哪几件事”，并真实构造测试输入，从第一步一直做到最终产出与下游使用。
2. **基于可见线索的穷举扫荡（Affordance-Only Sweep）**：
   - 严禁靠猜 URL 路径（如手敲 `/admin` 或 `/secret`）作弊；
   - 必须主动试探界面上的合理交互线索：空状态引导按钮、折叠面板、二级 Tab、鼠标悬停提示（Hover）、列表项右键菜单（`onContextMenu`）、文本选中操作、可拖拽区域、状态角标点击、顶部全局入口。
3. **交卷输出《主观功能地图》（Blind Mental Map）**：
   - **已自主跑通的工作流**：每条写明“自定目标 → 实际每一步点击路径 → 最终看到的成果截图”；
   - **做到一半卡死或放弃的流程**：写明在哪一步找不到出口、缺少什么引导或报错卡住；
   - **主观功能清单**：盲测员认为“这个软件一共就只有以下这些功能”。

## 三、 双向差集对账与双核心指标 (Ground-Truth Reconciliation)

盲测员提交《主观功能地图》后，主控立即将其与内部《全量底账》逐条比对，计算两项硬指标：
- **无提示功能发现率（Unguided Feature Discovery Rate）** = `Pass 1 主动发现功能数 / 底账总功能数 (X / N, %)`
- **无提示工作流完通率（Unguided Workflow Completion Rate）** = `Pass 1 完整达成 DoD 工作流数 / 底账总工作流数 (Y / M, %)`

每项功能与工作流归入以下四类定性标签：

| 状态标记 | 分类名称 | 判定条件 | 问题归因 |
| :---: | :--- | :--- | :--- |
| 🟢 | **自主顺畅跑通** | Pass 1 无需提示即自己发现入口并一次走完 DoD | 信息架构与引导优秀 |
| 🟡 | **绕弯试错跑通** | 走错 2 步以上、反复返回或靠瞎猜才完成 | 命名模糊、按钮层级不直观（`P2` / `P1`） |
| 🟠 | **发现入口但中途卡死** | 找到了功能入口，但缺下一步引导、校验无提示或状态断档导致无法达成 DoD | 流程断裂缺陷（`P0` / `P1`） |
| 🔴 | **幽灵功能（Ghost Feature）** | 代码里实打实存在，但盲测员在 Pass 1 **完全不知道有这功能**（0% 发现） | **进入第 2 轮目标补测** |

---

## 四、 第 2 轮：仅告知“用户目标”不告知“操作路径”的幽灵功能补测 (Pass 2 — Goal-Only Nudge)

针对 Pass 1 漏掉的所有 **🔴 幽灵功能 / 未触发工作流**，主控向同一盲测子代理（或新的受试者）下发第 2 轮补测指令——为了精确区分**“入口藏太深”**还是**“就算用户想用也根本走不通”**：

### 4.1 补测红线（仅给目标，严禁给路径）
- ✅ **合规下发**：“假设你现在作为真实用户，想要实现【把AI回答里的某段重点保存成长期记忆/知识卡片】，或者【把当前项目数据导出备份】。请**在没有任何操作提示的情况下**，自己去界面里找找看并试着把这件事做完。”
- ❌ **严禁剧透**：“去点击回答右下角的划词浮层…… / 去点左下角设置里的导出按钮……”

### 4.2 Pass 2 诊断分流
- **Pass 2 顺利找齐并跑通** → 定级 **`P1 - 可发现性 / 入口线索缺陷 (Discoverability Defect)`**：
  - 根因：用户只要知道“能做这事”就能做完，但界面本身没有任何视觉暗示（如右键菜单无图标提示、划词功能无新手提示、设置入口藏在折叠侧栏最底部）。
  - 建议修法：增加轻量空状态引导、显性操作按钮、Hover 提示条或首次引导气泡。
- **Pass 2 依然找不到入口或做到一半失败** → 定级 **`P0 - 流程断流 / 交互阻断缺陷 (Workflow Blocker)`**：
  - 根因：哪怕用户带着 100% 明确的真实目的满界面找，依然找不到入口、看不懂术语或流程在中途彻底断裂。必须优先修复！

---

## 五、 阶段二门禁与放行条件 (Stage 2 Gate)

1. 主控按 [audit-report-template.md](./audit-report-template.md) 模板二输出《阶段二：无提示全功能发现与工作流完通审计报告》，附上双核心指标（`X/N` 发现率、`Y/M` 完通率）与 `🟢 / 🟡 / 🟠 / 🔴` 全量对账表。
2. 在 `gate` / `stress` 模式下**暂停等待用户确认修改清单**（例如补充显性入口、修复断流提示、调整引导文案）。
3. 用户确认后，主控修改代码并启动**全新的盲测子代理**重新执行无提示探索验收；核心工作流跑通率与关键功能可发现性达标（或用户明确放行）后，标记 **`STAGE 2 PASSED`**，正式解锁阶段三。
