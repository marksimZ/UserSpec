# 阶段一审查细则：第一印象、观感与易读性 (Phase 1 Checklist)

本文档为阶段一盲测提供具体的诊断标尺。审查时**严禁站在开发者角度体谅实现难度**，必须完全代入“第一次打开这个软件、随时可能关掉走人的真实普通用户”。

---

## 1. 第一印象：5 秒直觉认知测试 (First Impression)

真实用户决定是否留在一个新软件通常不超过 5 秒。首屏加载完成后，在滚动或乱点之前，逐项核查：

| 检查项 | 合格标准（Pass） | 典型反模式 / 失败信号（Fail） |
| :--- | :--- | :--- |
| **产品定位传达** | 盲测员仅看首屏标题、副标题或核心工作区，就能准确说出软件核心用途（误差不超过同一细分品类）。 | 只有一句空洞口号（如“赋能下一代智能协同生态”）、只有一个无解释的项目代号 Logo，或者满屏零散模块看不出主业。 |
| **目标人群匹配** | 界面视觉气质与专业度契合目标用户（大众工具亲切直白，专业工具清晰高效）。 | 给普通消费者用的软件满屏命令行/JSON 配置项；或给高频办公用的工具堆满廉价闪烁特效干扰视线。 |
| **第一行动点（Primary CTA）** | 视线在 3 秒内能自然落到“我现在第一步该点哪里”（全屏唯一或最突出的主按钮/输入框）。 | 首屏同时出现 4～5 个同色高饱和度实心按钮争抢注意力；或者核心入口藏在角落不起眼的文字链/折叠菜单里。 |
| **登录墙价值前置** | 若首屏需登录/注册，页面清楚展示了产品价值或界面预览，并提供游客体验或极简注册。 | 打开就是一个孤零零的“请输入账号密码”表单，连软件名字和用途都没介绍，直接把新用户挡在门外。 |
| **冷启动心理负担** | 首次进入主工作台时，面对空界面也有清晰的 1-2-3 起步引导或示例模板。 | 进去就是一片惨白表格写着“暂无数据”，左侧十几个导航菜单不知道该先配置哪一个。 |

## 2. 观感：视觉秩序与审美工艺 (Visual Craft)

重点排查“开发直出半成品感”、“AI 廉价模板感”与“排版失序”：

### 2.1 视觉层级与空间呼吸感
- **主次分明**：页面标题、分区标题、正文、辅助说明在字重（Weight）、字号与灰度上是否有清晰梯度？还是所有文字几乎一般大、一般黑？
- **留白与密度**：内容卡片之间、文字与容器边框之间是否有舒适内边距（Padding）？是否存在文字紧贴边框（“顶天立地”）、按钮挤成一团，或超大屏幕上内容被无限拉宽导致视线左右横跨超过 30 厘米？
- **对齐强迫症检查**：同一行/同一列的卡片高度、图标中心线、表单标签与输入框左边缘、表格表头与单元格数据是否严格对齐？（哪怕偏离 `2px～4px` 也会产生明显的粗糙感）。

### 2.2 色彩、组件一致性与精致度
- **色彩克制与语义准确**：
  - 主色是否只用于核心交互与激活态？
  - 语义色是否符合直觉（红色仅用于危险/报错/删除，绿色用于成功/正常，黄色用于警告）？严查“取消/返回按钮涂成刺眼大红”或“普通标签五颜六色像调色盘”。
  - 深色模式（若开启或默认深色）是否存在刺眼纯白背景残留、深灰字叠黑底看不清、边框消失等问题？
- **组件风格统一**：圆角大小（如有的卡片 `0px` 直角、有的 `16px` 大圆角）、阴影浓淡、图标线条粗细（线性图标与实心面性图标混用）、按钮尺寸是否统一？
- **半成品痕迹清零**：
  - 是否暴露了未美化的浏览器原生滚动条（在深色卡片内出现一条白色粗滚动条）、原生 `select` 下拉框与自定义组件格格不入？
  - 是否有破损图片裂图图标、占位假文（`Lorem ipsum`、`测试数据123`、`TODO`）、文字超出容器被生硬腰斩且无省略号（`...`）及悬停全文提示？

### 2.3 多视口与窗口尺寸观感
- **Web 桌面端 + 手机端双视口**：
  - 桌面宽屏（`1440×900`）：两侧留白是否合理？主内容区是否居中且宽度受控？
  - 手机小屏（`390×844`）：是否出现**底部横向滚动条**？顶部导航栏文字是否折行重叠？卡片网格是否自适应转为单列？按钮与可点击元素间距是否足够手指点按（建议热区 `≥ 44×44px`）？
- **桌面客户端 / Electron 窗口**：
  - 默认启动窗口大小是否能完整展示首屏核心内容而无需用户立刻手动拉大窗口？窗口标题栏与内部界面配色是否割裂？

## 3. 易读性：文案友好度与“去开发腔” (Readability & Copy)

用户不关心系统底层怎么实现，只关心“这对我意味着什么、我该怎么做”：

### 3.1 排版扫读体验
- **对比度充足**：正文与背景对比度是否清晰？严查“浅灰背景配浅灰小字（如 `#999` 叠 `#F5F5F5`）”导致视力疲劳。
- **字号与行高**：桌面端正文一般不小于 `13px～14px`，移动端不小于 `14px`；多行段落行高建议在 `1.5～1.7` 之间，避免行距过密粘连。
- **数字与表格可读性**：金额、数量、时间等表格列是否对齐清晰（右对齐或等宽数字 `tabular-nums`）？单位（元、秒、MB、%）是否标示明确？

### 3.2 严抓“开发腔 / 系统黑话外露”（一票否决项）
一旦在界面上看到以下内容，直接标记为 `Blocker` 或 `Major`：
- **底层数据原样裸露**：
  - 界面直接渲染出 `null`、`undefined`、`NaN`、`[object Object]`、`true/false`。
  - 英文枚举值或常量直接当状态展示：如 `PENDING`、`IN_PROGRESS`、`ROLE_SUPER_ADMIN`、`TYPE_1`。
  - 未格式化的原始时间戳：如 `2026-11-24T10:28:59.123Z` 或毫秒级 Unix 时间戳。
  - 对用户毫无意义的数据库 UUID / 内部哈希长串直接占据主标题位置。
- **程序员思维文案**：
  - 把“保存个人资料”写成“提交实体变更 / 更新配置项”；把“还没有项目，点击新建”写成“查询结果集为空（0 rows）”。
  - 表单提示写正则表达式或字段名：如“字段 `user_nick` 长度需满足 `[a-zA-Z0-9_]{4,16}`”，而不是“昵称请使用 4～16 位字母、数字或下划线”。
- **语言混杂与术语不一致**：
  - 中文界面夹杂未翻译的英文按钮（一会儿 `Submit`，一会儿 `确定`，一会儿 `保存`）。
  - 同一个概念在左侧菜单叫“工作空间”，在弹窗标题里叫“项目组”，在提示语里又叫“租户（Tenant）”，让新用户以为是三个不同功能。

## 4. 阶段一严重度定级标准

- **`P0 - Blocker（阻断级，必须修完才准进阶段二）`**：
  - 5 秒测试完全看不懂软件用途，或根本找不到第一步核心入口；
  - 界面出现布局崩坏、文字重叠遮挡、裸露 `undefined`/代码枚举/堆栈信息；
  - 无法完成正常的新用户进入或登录页毫无价值说明且阻塞访问。
- **`P1 - Major（重要级，强烈建议阶段一修完）`**：
  - 视觉主次混乱、多个主按钮打架、明显对齐错位或对比度过低难以阅读；
  - 存在明显的“开发腔”文案、中英混杂、概念命名不统一或冷冰冰的空白“暂无数据”页；
  - 响应式手机视口或常规窗口尺寸下出现横向溢出、元素挤压变形。
- **`P2 - Minor（打磨级，可由用户决定本阶段顺手修或延后）`**：
  - 局部圆角/间距轻微不一致、次要图标表意不够精准、微小的留白比例优化建议。
